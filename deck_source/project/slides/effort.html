Inside LaCAM · search effort

LaCAM only searches when PIBT would get stuck

Left: for every solved instance, the number of configurations LaCAM generated divided by the makespan plus one. A value of 1 means the search never had to back up: it followed a single greedy PIBT rollout from start to goal. Split by whether plain PIBT solved the same instance: when PIBT succeeds, LaCAM generates exactly one rollout (median 1.00), so the search layer is free. When PIBT fails, the original LaCAM needs a median of 11 times more configurations, sometimes hundreds, but still solves 125 such instances. LaCAM* stays at 1.00 even on the 349 instances where PIBT failed, because the swap technique removes the corridor deadlocks before the search is needed. Right: the share of PIBT successors that were already explored, which is how LaCAM detects PIBT's cycles; for the original LaCAM on warehouse maps it is 20 to 30%.
