Caveats

Limitations and next steps

Limitations

  • One laptop, 4 runs in parallel: compare runtimes relative to each other, not as absolute numbers
  • One-shot MAPF; real warehouses assign new tasks continuously
  • Custom layouts use uniformly random tasks, not order profiles
  • 1.2 GB memory cap per run, binding for 25 original-LaCAM runs and for LaCAM* refinement
  • Baselines at default settings, e.g. EECBS with bound 1.2

Next steps

  • Lifelong planning: replan LaCAM* as robots receive new tasks
  • Refine LaCAM*'s first solution with LNS and measure the gap that remains
  • Warehouse task streams: pick stations, shelves, charging
  • Larger fleets (2,000+ agents) on the large warehouse maps
Limitations: all runs were on one laptop (Ryzen 7 7840HS, Windows 11) with four runs in parallel, so absolute times would differ on a server, but every planner faced the same conditions and was compiled with the same compiler and flags. The study is one-shot MAPF; a real warehouse is lifelong, with tasks arriving continuously, which is the next natural experiment. The custom layouts use uniformly random start and goal cells rather than realistic pick-station traffic. A 1.2 GB per-run memory cap was needed on this machine; it ended 25 original-LaCAM runs early (all on instances where it was struggling anyway) and limits LaCAM*'s refinement. The baselines were run at their default settings; for example EECBS with a larger suboptimality bound would be faster but costlier.
