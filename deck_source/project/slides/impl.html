I wrote LaCAM and LaCAM* from the papers in C++17, about 1,300 lines, with one PIBT routine shared by standalone PIBT, LaCAM and LaCAM*. Because the shared code is identical, the difference between PIBT and LaCAM in the results is exactly the effect of LaCAM's search. To validate the re-implementation I built the official LaCAM and LaCAM* code and ran both versions on 48 instances across all 12 maps with the same random seed. The outcomes agree on all 48 instances, including which ones fail within the time limit. Plans are identical in every instance the original LaCAM solves. For LaCAM* they are identical in 46 of 48 against the official code as published. I traced the other two to a bug in the official code: its distance table keeps a reference to a queue element after popping it, which is undefined behaviour and gives wrong distances under the Microsoft compiler, so its search starts with the wrong agent order (its output even shows an impossible makespan lower bound equal to the number of vertices). With that one line fixed, the official code and mine agree on all 48 instances. My version takes about 0.8 times as long at the median. The baselines are not re-implementations: they are the authors' own code, compiled with the same compiler and flags, with only Windows portability fixes.
