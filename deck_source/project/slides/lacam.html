One iteration

  1. Look at the configuration Q on top of the stack.
  2. Take Q's next constraint and add its children to the tree.
  3. PIBT moves all other agents, giving a new configuration Q′.
  4. Q′ is new: push it. Q′ seen before means PIBT is cycling: revisit the old node and keep trying constraints.

Complete: the trees eventually list every successor, so a solution is found whenever one exists.

LaCAM's high level is a depth-first search where each node is a configuration (the positions of all agents). Instead of enumerating the exponentially many successors, each node owns a constraint tree that is grown lazily: the root has no constraint, depth-1 nodes fix the next move of the highest-priority agent, depth-2 nodes also fix the second agent, and so on. Every visit pops one constraint and asks PIBT to complete the rest of the team. If PIBT produces a configuration that was already explored, that is exactly PIBT's livelock, detected; LaCAM goes back and tries different constraints. Because the trees eventually enumerate every successor, LaCAM is complete. Because PIBT's first suggestion is usually good, it is also very fast.
